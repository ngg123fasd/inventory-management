Request Data Flow
1
User changes a filter
FilterBar.vue updates one of 4 reactive refs inside useFilters.js. Because the composable is a module-level singleton (refs declared outside the function), all views share the same state instantly — no event bus needed.
2
View reacts and fetches
Each view watch()es the filter refs. On change it calls getCurrentFilters() (maps refs → plain object) and passes the result to the relevant function in api.js.
3
Axios sends HTTP GET
api.js builds a URLSearchParams string from the filter object (skipping 'all' values) and fires axios.get('http://localhost:8001/api/...'). No auth headers; no caching layer.
4
FastAPI filters in memory
main.py receives query params and passes the pre-loaded list (from mock_data.py globals) through apply_filters() (warehouse, category, status) and optionally filter_by_month(). Supports quarter strings like Q1-2025 or ISO months like 2025-01.
5
Pydantic validates & serialises
FastAPI runs the filtered list through the appropriate Pydantic model, then returns JSON. Any field mismatch between the JSON files and the model will surface here as a 422 error.
6
Vue updates computed properties
The view stores raw API results in a ref([]) (e.g. allOrders). All displayed values — totals, percentages, chart series — are computed() properties derived from that ref, so they update reactively without extra fetches.
Known Gaps
  • Tasks API missing api.js calls /api/tasks (used by TasksModal.vue) — endpoint not in main.py. Returns 404.
  • Purchase Orders API missing api.js calls /api/purchase-orders (used by BacklogDetailModal.vue) — not implemented. Returns 404.
  • Hardcoded KPIs Dashboard shows Inventory Turnover (4.2) and Avg Processing Time (8.5 days) as static strings — not returned by any API.
  • No frontend tests No Vitest or Jest config exists. Backend pytest suite only.
